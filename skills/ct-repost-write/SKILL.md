# Repurposed content (Nội dung tái sử dụng)

A method by Cuong Thach. Full source: https://cuongthach.com/docs/content-system/distribution/concepts/repurposed-content/ (Vietnamese: https://cuongthach.com/docs/vi/content-system/distribution/concepts/repurposed-content/). When this skill and the docs disagree, the docs win.

Reply in the user's language. It comes after a post is published, in Content distribution (Phân phối nội dung), the last step of the **Content system** (Hệ thống nội dung). Repurposed content is every version made from one blog post to reach another channel: email, a Facebook or X post, a community question, a YouTube video, a short video for Shorts and Reels, a podcast or an image. Each version changes only the form, never the ideas of the post.

## Before you start

Ask the user for:

- **The published blog post**, whole. Never a documentation page: docs carry no feeling, and one more cut makes a post that is completely dry. The blog post already runs on its core message.
- **The channels** they want, and who reads there.

If the post is not published yet, stop: this comes later.

## Rules for every version

1. **Keep the ideas exactly.** Take the brightest ideas of the post and keep each one as it is; never turn an idea around. If the version says one thing and the post another, the reader loses trust when they click through. No new angle either: a new angle is derivative content, a different job.
2. **Change only the form and the wording.** Rework the words to suit the channel and the group of readers you want to reach; the ideas stay as in the post.
3. **One idea per version on one channel.** Posting the same post on many platforms does not bore customers, since most follow you on one channel. What is wrong is posting the same idea many times on the same channel. Post different ideas one after another.
4. **Link back to the blog post**, never to the documentation: the post sits inside the Content funnel (Know - Trust - Love, Biết - Tin - Yêu), and the funnel leads to the sale.
5. **Let sent versions drift.** When the post is edited later, leave versions already sent alone; only remove one that carries something dangerous.

## The versions

| Version | What changes |
|---|---|
| Newsletter email | Gathers the post's brightest points, with a link to the post |
| Facebook or X post | Retells one bright point, with wording adjusted to the channel |
| Community question | Turns one idea of the post into a question for people to discuss, with the link to the post in the first comment |
| Long YouTube video | Turns the words into a video |
| YouTube Short, Reels | Cuts a bright point into a short video |
| Podcast | Turns the words into a voice |
| Images | Draws a new illustration for the idea of one H2 |

Five versions from one post is normal. Write each one ready to paste, and let the user post it themselves.

## The picture for a version

The picture that goes with a version is **a new illustration**: never a picture already in the post, never a cover with a title. It is drawn for the one idea that version carries, found the way you find an illustration for a post:

1. Find the H2 of the post the version takes its idea from.
2. Read that H2 to the end, and write its big idea in one sentence.
3. Find the contrast in that idea, then describe one picture as a metaphor for it. Show the user the H2, the big idea and the scene before anything is drawn.

Example: a community question asks "Where does your post usually get stuck?", taken from the H2 "Why do you keep writing but never publish?". The picture is a paper boat going round and round in a whirlpool, with a lighthouse close by that it never reaches.

- Painted more freely than the pictures in the post, in ink and watercolour.
- A picture with no words is hard to read, and one with many words is a mess: give it **one or two labels of one or two words each**, each with an arrow to the thing it names, like "Post" and "Publish".
- No title, no logo.

## What you never do

- Add an idea, story or number the post does not have.
- Start from a documentation page instead of the post.
- Post, comment or publish for the user.
